# 浏览器窗口与代理管理 · 当前视觉原型

[打开完整原型](index.html) · [公共视觉与交互](../../common/index.html) · [正式frontend规范](https://github.com/piqiu96/wt-media-workspace/blob/main/docs/standards/frontend/README.md) · [CHG099交付记录](https://github.com/piqiu96/wt-media-workspace/blob/main/delivery/completed/CHG-20261028-099/change.md)

当前最终可评审稿，含99个有效场景，其中19个为同步窗口完整状态，另有窗口状态读取中与失败Toast场景。左侧切换列表、详情、新建/编辑、代理选择、角色、异常及批量过程/结果。运营备注场景为 `?scene=w-note`：标签与正文14px、22px行高；信息到编辑区24px；标签/输入/辅助说明间8px。

index.html为唯一效果入口。assets中的base/interactions/scenes、sync-scenes、runtime-scenes、approved-decisions、图标和logo均为当前稿必需资源，standard.css/standard.js承载当前规范适配，公共颜色与控件引用../../common。approved-decisions包含缺失窗口默认展示、管理员团队筛选及代理列表只显示地区（供应商留在详情）的最终决策。它们不是历史稿，不可误删为缓存。

本目录不保存多版原型、修前/修后图、测试脚本、日志或生成过程文件；历史由Git承担，原则见[example入口](../../README.md#当前稿保留)。HTML为纯本地演示，不接业务服务，不进入Cloud/Desktop运行时；字段、权限和异常恢复以正式产品/合同及CHG为准。比特标签和窗口业务标签未在本期接入。

CHG099 已由用户完成整体走查并合入四仓主干；本原型保留为交互参考，真实运行结果以交付记录和已发布版本为准。

## 同步窗口 · 完整评审入口

[从读取开始走完整流程](index.html?scene=w-sync-reading) · [新增与变化确认](index.html?scene=w-sync-preview) · [同步成功](index.html?scene=w-sync) · [完成但有异常](index.html?scene=w-sync-issues)


画布上方的“同步状态预览”和“预览下一步”是评审工具，不属于真实产品界面。处理中由评审者切换下一状态，不用计时器制造成功；关闭按钮在处理中不可用。结果中的“处理”进入对应窗口异常，“返回同步结果”保留结果上下文。

保留原图23/24屏的居中容器、结果层级和密度；新增确认步骤依据当前CHG的扫描/确认服务。原图中的“安全字段自动更新”描述不能绕过当前服务的确认行为，也不恢复比特标签。

本原型不要求每次扫描都弹完整确认表：无变化和连接错误使用紧凑反馈；只有实际存在可确认变化时展示分区明细；确认后的结果只列已处理信息与待处理异常。真实产品必须根据实际响应选择状态，不照搬示例数字。

窗口日常列表默认展示全部窗口，独立“窗口状态”列显示“已找到 / 未找到”，列与筛选均位于运行状态之前；筛选仅有这两个选项，不选择就是全部，没有可选的“全部”项。单项危险操作统一写“删除”，悬停红字浅红底，最终确认才用红色实心。扫描后未找到的窗口可在列表直接核实，并从[清理已删除窗口](index.html?scene=w-cleanup)入口批量处理。单项和批量清理须先确认已在比特删除，并在[确认影响](index.html?scene=w-cleanup-confirm)后执行；账号保留、解除窗口关联，托管代理名额释放，窗口业务记录删除并留技术审计。再次同步时，历史缺失保留在独立标记的“历史待处理”区，可核实或删除，但不计入本次新增异常；[无异常结果](index.html?scene=w-sync)和[有异常结果](index.html?scene=w-sync-issues)均保留历史入口。管理员的运营团队筛选为名称或 ID 输入框，运营和高级运营不显示该筛选。代理列表只有管理员展示团队输入框，代理 ID 在原型与正式接口均为自增整数。原型的固定示例只用于交互评审，不映射实际数据库 ID。

代理信息列只呈现代理相关异常：配置不一致、代理到期、检测异常/未检测、代理资源不可用和代理结果待核实。“窗口缺失”属于窗口同步事实，在列表的“窗口状态”列、窗口详情、同步结果、核实窗口缺失与清理清单中展示，不附着在“直连”或代理地址下方。缺失期间不显示未经核实的代理配置结果。`直连` 是连接方式，不是异常状态。

代理名称或地址可点击查看只读详情：[系统托管代理](index.html?scene=w-proxy-info-managed)字段较多，使用侧栏；[比特自管代理](index.html?scene=w-proxy-info-self)字段较少，使用居中弹窗。直连不显示可点击入口。缺失窗口的代理信息仅代表最近同步记录；查看详情不触发检测、写入或展示认证秘密，“管理代理”保持独立操作。

## 窗口状态读取 · 已审批并落地

[正常列表](index.html?scene=w-list) · [正在读取](index.html?scene=w-runtime-reading) · [读取失败Toast](index.html?scene=w-runtime-error)

进入浏览器窗口页面或刷新页面时，本人 Desktop 自动读取一次本机窗口运行状态。页面右上角提供唯一的手动入口“刷新运行状态”，说明“只读取比特窗口的已打开或已关闭状态，不同步窗口资料。”不在列表表头或逐行展示刷新按钮。

- 不定时轮询，不自动重试；搜索、筛选、翻页、详情和普通资料重载不额外扫描。高级运营从他人视图回到本人视图时读取一次。
- 自动或手动读取失败只显示原因 Toast，按钮恢复可点击；不增加常驻错误条和独立“重试”入口。未取得状态的窗口显示“未知”，打开/关闭禁用，提示点击右上角“刷新运行状态”。
- 进行中显示加载并禁用重复点击。自动、手动和同步窗口共用同一进行中的扫描；同步返回的状态直接使用，保存后加载资料不再扫描一次。
- 系统内打开/关闭成功直接更新对应行；先关闭再停用和批量操作的原有安全校验保留。
- Web、管理员查看和高级运营查看他人资源不调用本机；切换视图或离开页面后，旧请求不得回写当前运行状态或弹出迟到错误Toast。
- “刷新运行状态”仅重读页面内存中的打开/关闭状态，不保存窗口资料、不修改代理关系、不检测账号或代理可用性；“同步窗口”仍负责窗口信息比对与保存。

手动读取成功提示“已读取 N 个比特窗口的运行状态。”；入页自动读取成功不弹提示。失败按原因提示：未绑定比特账号→“尚未绑定比特账号，请先到「个人信息」完成绑定。”；比特账号不一致→“比特登录账号与系统绑定账号不一致，请切换到正确账号后再试。”；比特未连接→“无法连接比特，请启动比特并确认已登录。”；本机服务不可用→“本机服务暂不可用，请重启桌面端后再试。”；其他读取错误→“读取运行状态失败，请确认比特已启动并登录，稍后再试。”自动和手动失败均不连续重试。

“核实窗口缺失”使用居中弹窗：简短原因、窗口名称/ID/托管代理/可执行状态、受影响账号及一行后续处理。[有关联账号](index.html?scene=w-missing)显示紧凑清单；[无关联账号](index.html?scene=w-missing&accountState=none)显示“暂无关联账号”，不渲染空表格。查询参数只切换本地评审示例，不进入运行时代码。

原型的画布外状态按钮只用于查看正常/读取中/失败效果；不调用服务或用计时器模拟业务成功。Cloud共用Vue已经采用以上规则，使用真实Local Agent扫描与明确的开关响应。

## 本轮核验范围

19个同步状态完成离线DOM结构和交互核验：全部使用居中Dialog，过程与简单异常没有空表格/七类批量统计；校验选择、分区、确认、异常处理返回及关闭路径。测试脚本与依赖仅置于系统临时目录。

原型已经作为 CHG099 的交互基准，Cloud 共用 Vue 候选已实现这 19 类状态；隔离 Cloud 页面和自动化可验证结构与流程，真实 Desktop 与比特窗口效果仍以 CHG099 验收记录为准。

## 动态代理提取

[提取预览](index.html?scene=p-extract) 展示本机返回的首条有效地址，确认后回填表单。本次仅提取，不保存资源，也不执行连接检测；保存后再点击“检测”。已有动态资源的“提取新地址并检测”会从本人 Desktop 调本机 Agent 提取，再由 Cloud 只更新连接字段并检测；已关联窗口不会自动改写。
