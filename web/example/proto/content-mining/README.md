## 评审方式

参考 social-accounts 组织为 **38 个场景**：内容池／发现／审核／批量 P01–P16，策略 S01–S10，任务 T01–T08，角色与异常 G01–G04。

- 顶部场景选择器切换场景，支持连续翻页或仅看产品；地址中的 `?scene=P10` 等支持直接定位。目录按需展开，不持续占用产品宽度。
- “本屏说明”按需展开走查问题、关注点与必要的演示控制。评审控件在产品画面外，抽屉打开时仍可切换场景。
- 场景切换重置样本；同一场景内可连续操作、跳转三页。产品页切换保留各自筛选、页码和选择。
- `index.html` 是唯一当前评审入口；`product.html` 为其内部产品画面，不是另一版方案。

## 主要体验

- **内容池：** 默认展示 ID、内容、类目、互动、来源、状态和发布时间；作者／平台随内容展示，也可在表头“展示列”中独立展开，入库时间等完整信息在列设置与详情中可达。避免为保留字段而默认堆满宽表；类目可搜索多选，高级条件下置，查询才生效；无封面、长标题、三种处理状态、选择适用数量及失败线索都有代表样本；保留表头排序。
- **主动发现：** ID／链接与关键词分开输入；搜索不写入，勾选后入池；继续加载保留选择，新查询重置选择；新增、重复与失败独立反馈。
- **审核与详情：** 审核采用左侧封面、右侧判断信息的独立布局，顶部显示当前进度，底部固定处理动作；冻结当前筛选范围队列；跳过保持待处理，转换失败停留原项，本轮结束可继续跳过项；审核备注随处理保存，失败保留草稿。详情保留内容、来源、处理记录与关联素材。原作品入口保留；样本未配置真实链接，只说明跳转边界。
- **批量处理：** 确认、处理中、结果三个阶段；互斥计数、逐项原因、素材团队去向和仅重试失败项。处理中不能关闭；在外部演示控制手动推进结果，不用定时器伪造成功。
- **策略：** 800px 长配置抽屉和分区定位；关键词以单一标签输入添加／移除，支持粘贴与去重；三种执行周期和优先级规则；保存失败保留输入，未保存离开保护；保留执行、启停、复制与删除。在途防重与无规则只入池均可评审。
- **任务：** 保留五种状态和五项业务统计；结果、执行过程、当次快照、异常记录按任务分区查看，页签支持方向键切换；发现内容使用当次关联逐项追溯；待执行未知结果用“—”；零新增仍可成功；重试生成关联新任务，原记录不改写；快照局部失败保留已知事实。
- **角色与容器：** 普通运营只读追溯、高级运营管理、管理员跨团队内容；转换去向跟随来源团队。宽屏完整侧栏、较窄桌面图标侧栏，也可手动切换；支持窄容器、表内横滚和弹层滚动，不整体缩小产品。

## 依据与边界

本次已只读查看当前运行产品的 `/content-pool`、`/discovery-strategies`、`/crawl-tasks`，同时核对 Cloud 源码与正式资料。现有运行环境未在本轮重新构建，这些观察用于设计核实，不作为当前源码的发布验收。

所有数据虚构，操作只修改内存，重载恢复。三个主列表默认各 8 条样本；管理员另有 2 条第二团队内容。发现固定候选按 3 条追加，最多 9 条；同一候选身份本页去重，不代表真实平台检索或完整链接识别。封面为本地排版示意，没有真实视频、外部跳转、持久化权限或后台执行。正式产品的周期刷新仅作拟用画面说明，原型不发送请求。

未新增博主搜索、平台、暂停／取消任务、流程编排或业务状态。规则组按当前实现表达；旧 PRD 阈值描述与现有实现的差异继续留在分析中，不因视觉稿实现而视为业务裁定。

## 已执行检查

Chromium 离线检查：38 个场景入口无脚本异常；45 项连续操作与边界断言通过，覆盖筛选草稿、审核队列、失败恢复、批量重试、勾选入池与去重、保存与离开保护、复制／删除、在途防重、父子任务、历史快照、角色和团队归属。检查 1600px、1366px 页面及 560px 产品容器；代表画面另做截图走查。

另有 16 项体验断言通过，验证默认列在 1600px／1366px 下无需横滚、展开完整列时保留选择且仅表内横滚、关键词添加与保存、规则排序不误提交、任务页签键盘操作及当次关联。

以上是原型验证，不替代真实 Vue、Cloud／Desktop、接口或业务验收，也不代表用户已确认视觉。
